# 送禮大作戰：遊戲設計文件

> 狀態：初始草稿。標記為「待討論」的內容尚未定案。

## 1. 核心概念

玩家在一段模擬情侶關係中，面對不同節日與紀念日，從數個選項中挑選禮物。禮物會觸發伴侶的反應並影響關係；錯誤累積可能導致分手，順利走過所有事件則能達成長久關係或其他結局。

## 2. MVP 驗證目標

第一版希望回答：

- 玩家是否能在沒有額外解說的情況下理解玩法？
- 玩家是否願意完成整局？
- 選擇結果是否有趣、合理或令人意外？
- 玩家是否願意重新遊玩，嘗試其他禮物？
- 玩家是否願意分享自己的結果？

## 3. 暫定核心循環

1. 玩家開始一段關係。
2. 遊戲顯示節日與當下情境。
3. 玩家查看並選擇一份禮物。
4. 角色回應，關係數值或狀態發生變化。
5. 若達成失敗條件，進入分手結局。
6. 否則前往下一個節日。
7. 完成最後一個節日後，依過程與狀態顯示結局。
8. 玩家可以重新遊玩或分享結果。

## 4. MVP 暫定範圍

| 項目 | 暫定內容 | 狀態 |
| --- | --- | --- |
| 主要角色 | 1 名或 1 條關係路線 | 待討論 |
| 節日數 | 14 個（含 1 個東京額外任務） | Prototype 確認 |
| 每回合禮物數 | 4 個 | Prototype 確認 |
| 關係系統 | 單一好感度或少量狀態 | 待討論 |
| 失敗結局 | 至少 1 個分手結局 | 待討論 |
| 成功結局 | 至少 1 個長久關係結局 | 待討論 |
| 玩家存檔 | 使用 `localStorage` | 暫定 |
| 帳號／後端 | 不包含 | 暫定 |

## 5. 待確認的設計問題

### 角色與敘事

- 玩家扮演固定角色、匿名玩家，還是可以選擇身份？
- 送禮對象是否只有一位？是否有性別或個性選擇？
- 故事是寫實、搞笑、荒謬，還是混合風格？
- 角色喜好是否一開始公開，或讓玩家從對話中推理？

### 禮物選擇

- 禮物是否有價格？玩家是否有總預算？
- 每個禮物只有好壞分數，還是會改變個性、信任、浪漫等多個屬性？
- 同一份禮物能否在不同節日出現？效果是否不同？
- 玩家選擇前能看到哪些提示？

### 失敗與結局

- 單次嚴重錯誤能否立即分手？
- 還是必須讓關係值降至門檻才會分手？
- 結局只由最終分數決定，還是也考慮特定選擇組合？
- 是否讓玩家在結局畫面看到每次選擇的回顧？

### 重玩與分享

- 一局預計花多少時間？
- 重玩時是否隨機更換禮物或事件？
- 分享內容是文字、結果卡片，還是帶有挑戰連結？

## 6. 初步資料模型

以下只用來協助討論，欄位尚未定案：

```js
const holiday = {
  id: "first_anniversary",
  name: "交往一週年",
  description: "對方似乎很期待今天……",
  giftOptions: [
    {
      giftId: "handmade_album",
      relationshipChange: 20,
      reaction: "你居然還留著這些照片！"
    }
  ]
};
```

資料 ID 應使用穩定的英文小寫名稱，畫面顯示文字則可以自由修改。GA4 分析也會使用 ID，避免修改中文名稱後造成報表資料被拆成兩份。

## 7. 初步遊戲狀態

```js
const gameState = {
  currentHolidayIndex: 0,
  relationshipScore: 50,
  selectedGifts: [],
  endingId: null
};
```

是否需要預算、信任、浪漫或角色個性等額外狀態，要等核心玩法測試後再決定。MVP 優先避免玩家看不懂的多重數值。

## 8. 初步畫面清單

1. 首頁／開始遊戲
2. 簡短玩法說明
3. 節日情境
4. 禮物選擇
5. 角色反應與關係變化
6. 分手或成功結局
7. 結果分享與重新遊玩

相鄰步驟可以放在同一畫面中切換狀態，不代表一定需要七個 HTML 頁面。

## 9. 分析指標

第一版優先觀察：

- 開始率：進入網站後有多少人開始遊戲
- 完成率：開始後有多少人抵達任何結局
- 各節日流失率
- 各禮物選擇比例
- 分手率與成功率
- 重新遊玩率
- 結果分享率

事件名稱與隱私原則記錄於 [`../AGENTS.md`](../AGENTS.md)。

## 11. 隨機選項 Prototype 規則

- 使用固定的五年事件順序，共 14 個事件。
- 每個事件顯示四個不重複的禮物選項。
- 東京出差土產只從四個東京專屬選項中抽取，因此每次都會出現這四項，但排列順序會隨機。
- 其他事件從一般禮物清單隨機抽取。
- 一般事件以兩次為一組，每組恰好有一次會出現婚戒；每輪開始時會隨機決定婚戒先出現在單數或雙數次的一般事件。
- 「重抽這一題」會更換一般禮物，但不改變該事件是否應出現婚戒。
- Prototype 暫時不計分；玩家選擇禮物後，選項會鎖定並停留 1 秒，再於同一畫面顯示暫用角色反應，5 秒後自動前往下一個事件。
