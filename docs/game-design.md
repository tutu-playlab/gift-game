# 送禮大作戰：遊戲設計文件

> 狀態：可公開測試的 MVP。本文記錄目前程式已實作的玩法；未來調整時要同步檢查 `js/data.js` 與 `js/game.js`。

## 1. 核心概念與驗證目標

玩家在一段模擬情侶關係中，面對不同節日與紀念日，從四個選項中挑選禮物。禮物會觸發女友反應並改變好感度；好感度歸零會提前分手，走完事件或選擇婚戒則會依條件進入不同結局。

目前公開測試主要觀察：

- 玩家能否在沒有額外教學的情況下理解玩法並完成一局
- 禮物選項與角色反應是否有趣、合理或令人意外
- 玩家是否願意重新遊玩並嘗試其他選項
- 玩家是否願意複製連結分享給朋友

## 3. 遊戲流程

1. 玩家從首頁按下「開始測試」。
2. 顯示事件名稱、共度天數、好感度與四個禮物選項。
3. 玩家選擇一份禮物後，其他選項鎖定並顯示角色反應。
4. 分數與統計更新，約 3 秒後自動進入下一題。
5. 好感度降到 0、選擇婚戒觸發特殊結果，或完成第 14 題時進入結局。
6. 結局頁顯示分數、男友類型、文案與統計；玩家可以複製遊戲連結或重新遊玩。

## 5. 禮物抽選規則

- 東京出差事件固定使用四個東京專屬禮物，只隨機調整排列順序。
- 其他事件從一般禮物清單抽選，每題至少包含一個加分與一個扣分選項。
- 產生新題目時排除前兩題出現過的普通禮物，避免連續三題重複。
- 每輪開始時隨機決定婚戒首次出現的間隔，之後每隔 2～3 個一般事件出現一次。
- 婚戒不受普通禮物的重複限制；同一題的選項不能重新抽取。

## 6. 計分、反應與統計

- 初始好感度為 30，最低 0、最高 100。
- 禮物分為大加分 `+10`、小加分 `+5`、中性 `0`、小扣分 `-10`、大扣分 `-20`。
- 正分反應為「哇！你好有心喔！」，中性反應為「恩～謝謝你」，負分反應為「啊...怎麼是這個？」。
- 每次產生負分計為一次「踩雷」；只有 `+10` 計為一次「神級送禮」。
- 求婚失敗本身不計入踩雷次數。

## 7. 婚戒與結局規則

選擇婚戒時依選擇前的好感度判定：

- 91～100：求婚成功，顯示 100 分「恭喜成為準新郎」。
- 60～90：扣 10 分後繼續遊戲。
- 0～59：立即進入求婚失敗，顯示 0 分「恭喜成為前男友」。

一般流程在好感度降到 0 時立即結束；若完成全部事件，依最後分數顯示：

| 分數 | 結局 |
| ---: | --- |
| 80～100 | 別人家的男友 |
| 60～79 | 戀愛求生高手 |
| 40～59 | 小心翼翼型男友 |
| 20～39 | 奇蹟生還型男友 |
| 1～19 | 快要放棄型男友 |
| 0 | 恭喜成為前男友 |

## 8. 程式資料與狀態

事件、一般禮物、東京禮物、婚戒、角色反應與結局內容集中在 `js/data.js`。每個事件、禮物與結局都有不隨顯示文案改變的穩定 `id`，供程式判斷與 GA4 彙整使用。遊戲流程與目前狀態由 `js/game.js` 管理，主要包含：

```js
const state = {
  currentIndex: 0,
  score: 30,
  mineCount: 0,
  godGiftCount: 0,
  options: [],
  recentOptionIds: [],
  history: [],
  pendingEnding: null,
  currentEndingId: null
};
```

目前遊戲進度只存在頁面記憶體，沒有寫入 `localStorage` 或傳送到工作室自有後端。玩家同意分析 Cookie 後，指定的遊戲互動代號會依下方分析事件送往 GA4。

## 10. GA4 分析事件

- 全站採用基本同意模式；玩家同意分析 Cookie 後才載入 GA4。拒絕時不載入 Google 標籤，也不送出遊戲事件。
- `game_started`：首次開始遊戲。
- `holiday_viewed`：顯示一個節日題目，包含 `holiday_id`。
- `gift_selected`：選擇禮物，包含 `holiday_id`、`gift_id` 與結果類型。
- `game_completed`：任何結局顯示時送出，包含 `ending_id`、結局分類、最終分數、完成題數，以及 `completion_status`。完整玩完 14 題時為 `full_run`，中途進入結局時為 `early_ending`。
- `relationship_ended`：分手或求婚失敗時額外送出。
- `game_restarted`：從結果頁重新開始。
- `result_shared`：成功複製遊戲連結。
- 所有遊戲事件都包含 `game_id: "gift-game"`，且不傳送姓名、Email、自由輸入文字或顯示文案。
